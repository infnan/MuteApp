# 静音开关

Android 7.0 及以上（minSdk 24）的独立原生应用，无第三方运行时依赖。
包名：`com.example.mutetoggle`；版本：1.0。

## 使用

1. 安装 `dist/MuteToggle.apk`，启动“静音开关”。首次使用若尚未授权，会进入系统的“勿扰模式访问权限”设置，请允许该应用。授权步骤不执行切换，返回后重新启动应用。
2. 正常响铃状态下启动：调用 Android `AudioManager.setRingerMode(RINGER_MODE_SILENT)`，确认状态后 Toast：“已开启静音”。
3. 静音或振动状态下启动：切换至 `RINGER_MODE_NORMAL`，恢复零音量，确认后 Toast：“已关闭静音”，并播放当前系统默认通知提示音。

没有应用操作页面、常驻通知或后台服务；仅使用透明入口 Activity，不出现在最近任务中。恢复时透明入口短暂保留以完成音量核验和提示音，随后退出。处理中的重复启动合并，不重复翻转状态；下次启动重新读取系统真实状态，不依赖应用保存的开关。

## 音量恢复

- 先退出静音，等待 250 毫秒，再逐项读取音量；随后重试并再次核验，避免固件延迟恢复音量。
- 覆盖六种 Android 标准音量流：铃声、通知、媒体、闹钟、通话、系统。包含常见的媒体／通话／铃声通知／闹钟四类；部分固件会关联铃声、通知和系统音量。
- **仅将当前为 0 的音量设置为 3**，非零值保持不变。不把所有音量强制统一为 3；最大档位不足 3 时使用设备允许的最高档，最低档限制也予以遵守。不弹出系统音量面板。
- 如果设置被系统拒绝，或核验后仍有零音量，会提示“已关闭静音，但部分音量未能恢复，请检查系统音量”，并在 `adb logcat -s MuteToggle` 中记录对应音量流。
- 仅使用 Android 的原生静音模式，不额外将媒体、闹钟和通话音量清零；这些声音在静音期间是否继续响，由目标固件的静音规则决定。
- 未猜测或调用厂商私有音量编号。若对讲机的第四种音量为独立的 PTT／对讲音量，而不是上述标准流，其适配需要该设备的实际音量映射或厂商 SDK；当前不能保证该私有音量已覆盖。

## 恢复提示音

使用 `RingtoneManager` 播放系统默认通知音，通过通知音量通道输出；默认通知音设为“无”时，依次尝试系统默认铃声、闹钟音。都不可用时使用系统内置确认音。提示音最多播放约 2 秒，不申请音乐播放权限、不读取媒体文件、不常驻后台。不关闭用户另行设置的勿扰模式、不绕过音频路由和设备策略，因此独立勿扰规则、耳机或蓝牙路由仍可能影响实际听感。

## 构建

需要 JDK 17 或 21、Android SDK Platform 35、Build Tools 35.0.0。

```powershell
.\tools\build-apk.ps1
```

默认只读复用相邻 `HotspotApp/.tools/android-sdk`，也可传入 `-SdkPath`、`-JdkPath`。脚本自动处理中文路径，输出签名 APK 到 `dist/MuteToggle.apk`，使用本项目 `.tools/mute-debug.keystore`，后续更新须保留此签名密钥。此签名为本地测试用途，非应用商店发布证书。

也提供标准 Gradle 工程。配置 `local.properties` 中的 `sdk.dir` 后，可运行 `gradlew.bat :app:assembleDebug :app:lintDebug`。Gradle 默认调试签名与构建脚本签名可能不同，覆盖安装请始终使用同一种构建方式。

## 真机验收

- 未授权：仅进入系统授权页，不修改静音或音量；授权后再次启动才切换。
- 正常模式：启动后变静音，只显示“已开启静音”，不播放提示音。
- 静音／振动模式：启动后恢复响铃、显示“已关闭静音”，播放系统提示音。
- 在系统设置分别将四种音量设为 0，恢复后确认其为 3；将其设置为 1、2、5 等非零值后确认不被覆盖。
- 使用设备物理旋钮、PTT、耳机及蓝牙分别验证；特别检查厂商专用对讲音量是否映射为标准流。
- 连续触发、旋转屏幕、从最近任务重建或撤销授权，不应重复切换或误报成功。
