# 静音开关

Android 7.0 及以上（minSdk 24）的独立原生应用，无第三方运行时依赖。
包名：`com.example.mutetoggle`；版本：1.6。

## 使用

1. 安装或覆盖安装 `dist/MuteToggle.apk`，启动“静音开关”。直接尝试 Android 的静音切换，不再以勿扰权限查询结果作为启动前提。
2. 正常响铃状态下启动：调用 Android `AudioManager.setRingerMode(RINGER_MODE_SILENT)` 后，立即在同一回调中显示 Toast：“已开启静音”，并发起 0.3 秒振动；两者之间不插入延时。不等待、不核验静音是否成功，设置 API 即使报错也照常触发这两个反馈，错误只记日志。不播放提示音。
3. 静音或振动状态下启动：发出 `RINGER_MODE_NORMAL` 设置指令后，延迟 0.1 秒直接播放一声极短 beep，保留通知通道，不再查找或播放 `zhytera`。不等待、不检查恢复是否成功来决定是否启动声音，设置 API 即使报错也照常安排播放。原有响铃状态核验和仅通信音量的零值恢复独立进行，不影响播放启动时间。
4. 恢复响铃时，只有切换 API 确实抛出权限异常、且等待核验后仍未切换成功时，才考虑授权引导。如果系统报告已经授权，则仅提示实际操作失败；否则最多自动打开一次系统授权页，之后即使未授权或授权被撤销也不反复跳转，只用 Toast 提示手动授权。授权页返回后再次启动应用。发出开启静音指令后的反馈不受此授权核验流程阻塞。

没有应用操作页面、常驻通知或后台服务；仅使用透明入口 Activity，不出现在最近任务中。透明入口短暂保留以完成核验、振动或提示音，随后退出。处理中的重复启动合并，不重复翻转状态；下次启动重新读取系统状态，不依赖应用保存的开关。仅保存“已引导授权”标记。

## 状态核验

开启静音不再进行设置后的状态核验：按用户要求，发出设置指令后直接 Toast 和振动，不再出现静音结果“未确认”的提示。此时“已开启静音”是按请求发出的反馈，不代表应用额外验证了固件执行结果。

恢复响铃仍保留原有流程：每隔 250 毫秒检查，最多等待 2 秒，同时参考系统铃声模式查询与公开的铃声模式粘性广播；下次启动也参考该广播。API 报错但系统实际已达到恢复目标时，按恢复成功处理，不跳转授权页。恢复 API 没有报错但始终没有确认到目标模式时，提示“已发送静音切换指令，系统尚未确认状态”。振动或提示音错误不会把切换改报为失败。

## 音量恢复

- 先退出静音，等待 250 毫秒，再读取通信音量；随后重试并再次核验，避免固件延迟恢复音量。
- **仅检查通信／通话音量 `AudioManager.STREAM_VOICE_CALL`：为 0 时设置为 3，非零时保持不变。** 铃声、通知、媒体、闹钟和系统音量不参与读取、恢复或结果核验，即使这些音量为 0 也不会因此警告。
- 通信音量最大档位不足 3 时使用设备允许的最高档，最低档限制也予以遵守。不弹出系统音量面板。
- 如果通信音量设置被系统拒绝，或核验后仍为零，会提示“已关闭静音，但通信音量未能恢复，请检查通信音量”，并在 `adb logcat -s MuteToggle` 中记录对应音量流。
- 仅使用 Android 的原生静音模式，不额外将媒体、闹钟和通话音量清零；这些声音在静音期间是否继续响，由目标固件的静音规则决定。
- 已由用户确认：目标机器的四类音量为通话、铃声、媒体、闹钟；无线电通信使用通话音量。四类默认不同步，用户可以在系统中设置同步。本次仅按要求限制应用直接恢复的音量流，不调整同步设置；若系统启用了音量同步，由固件自行决定联动行为。
- 用户已确认原生静音不会让无线电通信静音，且这符合预期。本应用保留这一行为，不为无线电另行静音、不在开启静音时将通话或其他音量清零、不增加厂商私有控制。

## 恢复提示音

固定使用 Android `ToneGenerator` 在通知通道播放一次 `TONE_PROP_BEEP`，时长上限 120 毫秒，音量参数为 100。不再查询系统音频目录，不再加载或播放 `zhytera`，不改系统默认通知音设置。

恢复设置指令发出后延迟 100 毫秒调用播放逻辑，不等待状态轮询或通信音量恢复。beep 使用通知通道，不修改音频路由或通知音量。不增加文件查找／解码等待，不宣称硬件精确 100 毫秒出声。短 beep 播放结束不会取消后续通信音量恢复。后续原有状态核验不决定提示音是否启动。

不需要额外音频文件或存储授权。不常驻后台，不关闭用户另行设置的勿扰模式，不绕过音频路由和设备策略，因此独立勿扰规则、耳机或蓝牙路由仍可能影响实际听感。

## 构建

需要 JDK 17 或 21、Android SDK Platform 35、Build Tools 35.0.0。

```powershell
.\tools\build-apk.ps1
```

默认只读复用相邻 `HotspotApp/.tools/android-sdk`，也可传入 `-SdkPath`、`-JdkPath`。脚本自动处理中文路径，输出签名 APK 到 `dist/MuteToggle.apk`，使用本项目 `.tools/mute-debug.keystore`，后续更新须保留此签名密钥。此签名为本地测试用途，非应用商店发布证书。

也提供标准 Gradle 工程。配置 `local.properties` 中的 `sdk.dir` 后，可运行 `gradlew.bat :app:assembleDebug :app:lintDebug`。Gradle 默认调试签名与构建脚本签名可能不同，覆盖安装请始终使用同一种构建方式。

## 真机验收

- 未授权但固件允许切换：直接完成切换，不打开授权页；系统确实拒绝且状态未改变时只自动引导一次，再次启动不重复打开授权页。
- 正常模式：发出静音指令后，不管系统状态读数是否更新、设置是否报错，都立即显示“已开启静音”并同时发起 0.3 秒振动，不播放提示音、不等待确认。
- 静音／振动模式：启动后恢复响铃、显示“已关闭静音”，在恢复指令后延迟 0.1 秒，仅播放一声极短 beep。
- 通信音量为 0 时，恢复后确认为 3；通信音量为 1、2、5 等非零值时保持不变。关闭系统音量同步后，将其他音量设为 0，确认应用不补音量、不因这些零音量警告。
- 使用设备物理旋钮、PTT、耳机及蓝牙分别验证；确认无线电通信不受本应用开启原生静音的额外干预。
- 连续触发、旋转屏幕、从最近任务重建或撤销授权，不应重复切换或误报成功。
